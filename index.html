How it works

1. Pick a file and a password.
2. ALIP ENCRYPTOR derives a 256-bit key from your password with PBKDF2-SHA256 (250,000 iterations) and a random salt.
3. The file is encrypted with AES-256-GCM, which also authenticates the data — so decryption with the wrong password fails loudly instead of returning garbage.
4. Your password is never stored, logged, or transmitted anywhere. If you lose it, the file cannot be recovered — there is no backdoor.

Run locally — HP Android (Termux)

pkg update && pkg upgrade
pkg install nodejs git
git clone <repo-url> alip-encryptor
cd alip-encryptor
npm install
npx http-server . -p 8080
# then open http://localhost:8080 in Chrome Android

cd alip-encryptor
npm install

Deploy to hosting

This is a 100% static site (HTML/CSS/JS) — it deploys anywhere that serves static files:

  • Netlify / Vercel / Cloudflare Pages: connect the repo, no build command needed, publish directory = project root.
  • GitHub Pages: push to a repo, enable Pages on the main branch.
  • Any VPS/Nginx/Apache: copy the folder into the web root and serve over HTTPS.

Always serve over HTTPS in production — the Web Crypto API requires a secure context (HTTPS or localhost) to work at all.

Testing checklist

Encrypt: TXT, PDF, PNG, ZIP, JS, and binary files · correct and incorrect passwords · empty file · corrupted .alipenc.
Decrypt: round-trip against every file above · compare SHA-256 of original vs. decrypted output.
Obfuscator: JS obfuscation correctness (run the output) · HTML/CSS/JSON minification · unsupported-language messaging.
Download: single file, ZIP of many files, on Chrome Android and desktop browsers.
UI: all buttons, progress bars, cancel/reset, error states, small-screen layout.

FAQ & Security

How ALIP ENCRYPTOR actually protects your data — and what it can't do.

Does my file ever leave my device?

No. Encryption, decryption, and obfuscation all run inside your browser with the Web Crypto API and local JavaScript. Nothing is uploaded to a server.

What encryption does it use?

AES-256-GCM (authenticated encryption) with a key derived from your password via PBKDF2-SHA256 at 250,000 iterations, using a random 16-byte salt and 12-byte nonce per file.

What happens if I forget my password?

The file cannot be recovered. There is no backdoor, no master key, and no "forgot password" option — that's what makes the encryption real.

Is code obfuscation the same as encryption?

No. Obfuscation makes code harder to read; it does not make it secret. Anyone with the obfuscated file can still technically run or deobfuscate it with effort. Treat it as a deterrent, not a vault.

Why can't it obfuscate Python/PHP/Java/C/C++?

Honest answer: those need a real per-language parser or compiler toolchain, which isn't something a browser-only build can do correctly without faking the output. ALIP ENCRYPTOR says so instead of shipping broken code.

Is history stored anywhere?

Only if you turn it on, and only on your device via localStorage. It logs filenames, operation type, timestamps, and status — never passwords or file contents.

About

ALIP ENCRYPTOR is a local-first toolkit for encrypting files, decrypting them back, and obfuscating source code — built to run entirely in the browser, with Android/Chrome Android as a first-class target alongside desktop. Version 1.0.0.
